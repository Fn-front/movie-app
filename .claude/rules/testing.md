# テスト作成ルール

## 【必須】配置・カバレッジ

- テストファイルは対象ファイルと同じディレクトリに `<filename>.test.ts(x)` で配置する
- テストカバレッジは全指標（Statements, Branches, Functions, Lines）で**80%以上**を維持する
- カバレッジが80%を下回る変更はPRに含めない

## 【必須】テスト手法

- アクセシビリティ優先クエリを使用する（getByRole, getByLabelText 等）
- ユーザーイベントシミュレーションには `@testing-library/user-event` を使用する
- コンポーネント・フック・API Routeそれぞれに対応するテストを作成する

## 【必須】ユーザーストーリーの網羅性（最優先）

ハッピーパスだけで「カバー済み」としない。各ユーザーストーリーについて、**下記の観点チェックリストを毎回照合**し、該当する観点は必ずテストする（観点をその都度ゼロから考えず、リストで漏れを防ぐ）。

### 観点チェックリスト（該当するものを網羅）

- [ ] **正常系**（主要ハッピーパス）
- [ ] **入力バリデーション**（形式不正 / 必須未入力 / 上限・下限 / 不一致）
- [ ] **認証・認可**（未認証アクセス → リダイレクト/誘導、権限不足）
- [ ] **空状態・0件**表示
- [ ] **期限切れ / タイムアウト / 試行回数上限**
- [ ] **エラー応答**（API失敗 / サーバーエラー / ネットワーク不通）
- [ ] **重複・競合**（既存と重複、再送クールダウン、同時操作）
- [ ] **状態保持・遷移**（リロード後の保持、戻り先 callbackUrl）
- [ ] **セキュリティ**（オープンリダイレクト等の拒否、サニタイズ）
- [ ] **レスポンシブ / アクセシビリティ**（SP表示、キーボード操作）

### 運用

- 機能を扱う際は、アプリの**全ユーザーストーリー（画面・ジャーニー）を洗い出し**、E2E未カバーのものは Issue 化する（既存機能の遡及的なギャップも対象）
- ※ 行カバレッジ80%（上記）を満たしても**ストーリー網羅とは別概念**。高カバレッジでも異常系ストーリーの欠落はあり得るため、網羅性は本リストで別途担保する
